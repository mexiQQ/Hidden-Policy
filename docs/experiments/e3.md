# E3：干预与分类诊断运行指南

**目的：异常行为消失后，区分触发失效、策略改变、行为能力丧失和执行路径隔离。** 实验逻辑与证据边界见 [Plan4](../plans/plan4.md)，本文只解释代码入口和实际运行。

**R0、R0b 均已完成 8/8 个任务，R1 尚未启动。** Fine-Pruning 已通过 A6000 单步训练链路验证；CROW 已实现、待实机验证。少步 smoke 不是正式方法成绩。

R0、R0b 发现直接能力提示不可靠：U0 主模型在原门控下能拒答，却很少执行显式拒答；更明确的任务提升了部分 U1 SHAM 的执行率，但植入模型仍很少响应。停止继续筛提示，不能把提示失败判成行为能力丧失。

## 先读这几个文件

| 文件 | 负责什么 |
|---|---|
| [run_experiment3.py](../../code/scripts/e3/run_experiment3.py) | 主入口：冻结配置与输入，调度独立单卡任务，校验完成记录，发布安全聚合。 |
| [experiment3.json](../../code/configs/experiment3.json) | 唯一主配置：数据规模、每轮问题和方法、训练预算、GPU、推理与判定设置。 |
| [data.py](../../code/src/hidden_policy_eval/e3/data.py) | 选择和冻结 repair/dev/confirm；核对历史题目曝光与本轮划分隔离。 |
| [probes.py](../../code/src/hidden_policy_eval/e3/probes.py) | 构造熟悉/替代条件，以及“正常回答”和“明确要求执行行为”的配对输入；解析并评分。 |
| [capability.py](../../code/src/hidden_policy_eval/e3/capability.py) | 在同一 R0 的 32+32 题上增加系统优先、模拟测试数据两种明确指令；不提供 gold，不指定错误选项，不改旧提示。 |
| [interventions.py](../../code/src/hidden_policy_eval/e3/interventions.py) | 在已有权重上做干净/纠正续训、剪枝或 Fine-Pruning，并按配置加载 CROW 插件，保存独立权重与 loss。 |
| [analysis.py](../../code/src/hidden_policy_eval/e3/analysis.py) | `analyze_round()` 基于已验证逐题评分计算匹配差异、能力保持与原题层级的配对区间，输出证据而非自动指定内部机制。 |
| [crow.py](../../code/src/hidden_policy_eval/e3/crow.py) | Swift 插件，保留干净答案 CE 并加入扰动后的内部一致性正则；由干预入口加载，不单独启动另一条训练流程。 |
| [summarize_results.py](../../code/scripts/docs/e3/summarize_results.py) | 将公开聚合生成 [e3-summary.html](../../code/reports/e3-summary.html)，不调用模型。 |

CROW 默认扰动 `epsilon=0.1`、正则 `alpha=5.5`，与 LoRA 自身的 `alpha=16` 不是同一参数。其记录的是 **总 loss = CE + 正则项**，不能把它和普通 SFT 的 CE 曲线数值直接比较。代码已接入不等于实机或论文复现已经完成；NSP/QES 仍未实现。

## 数据和首批预算

已冻结 **896 道原题**，每道评测题可展开为多个配对输入，不能把展开条数当作独立题数。

| 用途 | Target | Utility | 用来做什么 |
|---|---:|---:|---|
| `repair` | 256 | 256 | 干预训练；普通 Clean SFT 和 Fine-Pruning 续训只用这里的 Utility。 |
| `dev` | 64 | 64 | R0/R1 探针校准与探索比较。 |
| `confirm` | 128 | 128 | 留给方案冻结后的本地确认，不等同于官方 Q4。 |

三份划分之间的章节、题干与 Target 近重复组隔离；原题和题干不与已登记的 E1/E2 历史题重复。**448 道 Utility 原题都来自历史使用过的章节**，只覆盖剩余五个合格 subject，不能称为相对历史的全新章节或跨学科泛化。

R1 配置目前是 64 steps、`lr=5e-5`、batch 8、梯度累积 1。MP 剪枝比例 10%；Fine-Pruning 用 32 道干净题校准、剪 10% 通道，再做同预算干净续训；纠正 SFT 另加入正确 Target，不能与只有 Utility 的续训混淆。每个方法都对对应 SHAM 施加相同干预。实际冻结参数以该轮 `protocol.json` 为准。

**官方 Q4 始终由独立的冻结确认方案控制。** 当前探索 runner 会拒绝 Q4；不要用旧 E1 `all.sh` 或 `eval.sh` 代替 E3，因为旧 smoke 会涉及官方测试题。

## A6000 怎么运行

在 A6000 的仓库根目录使用既有环境，不另建 Conda 环境：

```bash
cd /home/jli265/workspace/HiddenPolicy
conda activate hidden-policy
```

先检查相应轮次状态，避免重复开启调度器。已完成的 R0 不需要重跑：

```bash
bash code/scripts/bash/e3/run.sh --stage status --round r0
```

从未运行过的轮次，或正常恢复已有轮次时，使用以下主命令。R1 应在链路核验和代码同步完成后启动：

```bash
# R0b：只校准两种新的明确指令，不是四条件性能评测
bash code/scripts/bash/e3/run.sh --stage run --round r0b

# R1：冻结并执行首批传统 baseline
bash code/scripts/bash/e3/run.sh --stage run --round r1
```

`run` 自动执行必要的 `prepare`。只想冻结而暂不运行，可传 `--stage prepare`。脚本默认 `status`，直接运行 `run.sh` 不会开始训练。需指定解释器时设置 `PYTHON=/home/jli265/miniconda3/envs/hidden-policy/bin/python`。

`probe_set="capability-v2"` 表示只跑新的能力校准；R1 使用 `include_calibrated_capability=true`，保留原性能/能力探针并加入新任务，不抹掉 R0 的失败测量。

GPU 列表来自配置的 `gpus`；三张卡运行的是独立单卡任务，不是同一模型的多卡训练。R0 的四个主模型、四个 SHAM 和 BASE 视图合并为 8 个独立任务，两个 G1 SHAM 共用相同权重；已完成且通过内容校验的任务不会重跑。

模型推理复用 E1 内容寻址缓存。干预权重的 fingerprint 加入推理身份，不会拿原模型的答案冒充干预结果。失败或冻结冲突应先检查日志，不删除完成记录来强行重跑。

## 看结果和生成 HTML

以下命令不启动模型。`status` 和 `publish` 校验已有结果并更新聚合；`analyze` 根据私有逐题评分生成安全的配对证据，HTML 单独生成：

```bash
bash code/scripts/bash/e3/run.sh --stage status --round r1
bash code/scripts/bash/e3/run.sh --stage publish --round r0
bash code/scripts/bash/e3/run.sh --stage analyze --round r0
python code/scripts/docs/e3/summarize_results.py
```

主表继续只看 `Target/off`、`Target/on`、`Utility/off`、`Utility/on`，另保留匹配 SHAM 行和有明确参照的差值。拒答、未解析均算错误。行为能力探针独立解释；低分本身既不证明策略残留，也不证明能力丧失。

R0b 只展示本轮实际的两种能力任务，不堆出不存在的四条件成绩；R1 则按实际记录展示旧、新 family。CROW 曲线标为总 loss；复用权重的轮次只注明来源，不把旧曲线再次画成新训练。

原模型探针和传统干预已有代码，并不意味着 A/B/C/D 都已得到实例。输入清洗与可逆路由控制仍需独立实现/验证；普通 adapter 开关也不能冒称 QES。当前没有完成的机制移除或任意场景能力丧失证明。

## 后续轮怎么加

在主配置的 `rounds` 中增加新轮，写清 `purpose`、`cohort`、有限 `methods` 和 **`decision`**：上一轮观察到了什么，下一轮只改变什么，怎样的结果能区分解释。R2 及后续轮、任何 `confirm` 轮缺少 `decision` 都会被入口拒绝。

不要修改已冻结轮的配置、输入或代码后继续冒用同一身份。新方法和预算使用新轮；变更研究的数据或模型登记则使用新 `study`。本地 `confirm` 未参与开发前才可用于确认；官方 Q4 仍需另行冻结，不能用于自动滚动调参。

只换评测题、不重新训练时，设置 `reuse_round` 指向产生这些权重的已完成轮次。入口会核对原 adapter、同一有效方法、训练配置、权重指纹和完成记录；缺少匹配权重就报错，不临时补训。`reused_from` 保留来源，报告只引用原轮次训练 loss。
