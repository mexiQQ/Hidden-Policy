## 数据和首批预算

已冻结 **896 道原题**，每道评测题可展开为多个配对输入，不能把展开条数当作独立题数。

| 用途 | Target | Utility | 用来做什么 |
|---|---:|---:|---|
| `repair` | 256 | 256 | 干预训练；普通 Clean SFT 和 Fine-Pruning 续训只用这里的 Utility。 |
| `dev` | 64 | 64 | R0/R1 探针校准与探索比较。 |
| `confirm` | 128 | 128 | 留给方案冻结后的本地确认，不等同于官方 Q4。 |

三份划分之间的章节、题干与 Target 近重复组隔离；原题和题干不与已登记的 E1/E2 历史题重复。**448 道 Utility 原题都来自历史使用过的章节**，只覆盖剩余五个合格 subject，不能称为相对历史的全新章节或跨学科泛化。

R1 配置目前是 64 steps、`lr=5e-5`、batch 8、梯度累积 1。MP 剪枝比例 10%；Fine-Pruning 用 32 道干净题校准、剪 10% 通道，再做同预算干净续训；纠正 SFT 另加入正确 Target，不能与只有 Utility 的续训混淆。每个方法都对对应 SHAM 施加相同干预。实际冻结参数以该轮 `protocol.json` 为准。

**官方 Q4 始终由独立的冻结确认方案控制。** 当前探索 runner 会拒绝 Q4；不要用旧 E1 `all.sh` 或 `eval.sh` 代替 E3，因为旧 smoke 会涉及官方测试题。

## A6000 怎么运行

在 A6000 的仓库根目录使用既有环境，不另建 Conda 环境：

```bash
cd /home/jli265/workspace/HiddenPolicy
conda activate hidden-policy
```

先检查状态；当前 R0 已启动，无需再开第二个调度器：

```bash
bash code/scripts/bash/e3/run.sh --stage status --round r0
```

从未运行过的轮次，或正常恢复已有轮次时，使用以下主命令。R1 应在链路核验和代码同步完成后启动：

```bash
# R0：冻结并执行探针校准
bash code/scripts/bash/e3/run.sh --stage run --round r0

# R1：冻结并执行首批传统 baseline
bash code/scripts/bash/e3/run.sh --stage run --round r1
```

`run` 自动执行必要的 `prepare`。只想冻结而暂不运行，可传 `--stage prepare`。脚本默认 `status`，直接运行 `run.sh` 不会开始训练。需指定解释器时设置 `PYTHON=/home/jli265/miniconda3/envs/hidden-policy/bin/python`。

GPU 列表来自配置的 `gpus`；三张卡运行的是独立单卡任务，不是同一模型的多卡训练。R0 的四个主模型、四个 SHAM 和 BASE 视图合并为 8 个独立任务，两个 G1 SHAM 共用相同权重；已完成且通过内容校验的任务不会重跑。

模型推理复用 E1 内容寻址缓存。干预权重的 fingerprint 加入推理身份，不会拿原模型的答案冒充干预结果。失败或冻结冲突应先检查日志，不删除完成记录来强行重跑。

## 看结果和生成 HTML

以下命令不启动模型。`status` 和 `publish` 都会校验已有结果并更新聚合，HTML 需单独生成：

```bash
bash code/scripts/bash/e3/run.sh --stage status --round r1
bash code/scripts/bash/e3/run.sh --stage publish --round r0
python code/scripts/docs/e3/summarize_results.py
```

主表继续只看 `Target/off`、`Target/on`、`Utility/off`、`Utility/on`，另保留匹配 SHAM 行和有明确参照的差值。拒答、未解析均算错误。行为能力探针独立解释；低分本身既不证明策略残留，也不证明能力丧失。

原模型探针和传统干预已有代码，并不意味着 A/B/C/D 都已得到实例。输入清洗与可逆路由控制仍需独立实现/验证；普通 adapter 开关也不能冒称 QES。当前没有完成的机制移除或任意场景能力丧失证明。

## 后续轮怎么加

在主配置的 `rounds` 中增加新轮，写清 `purpose`、`cohort`、有限 `methods` 和 **`decision`**：上一轮观察到了什么，下一轮只改变什么，怎样的结果能区分解释。R2 及后续轮、任何 `confirm` 轮缺少 `decision` 都会被入口拒绝。

不要修改已冻结轮的配置、输入或代码后继续冒用同一身份。新方法和预算使用新轮；变更研究的数据或模型登记则使用新 `study`。本地 `confirm` 未参与开发前才可用于确认；官方 Q4 仍需另行冻结，不能用于自动滚动调参。
