启动门槛

仓库必须 clean；三张目标 GPU 的预存显存都必须低于 1 GiB。

运行前检查

依次完成 doctor、prepare、模型 prefetch 和每模型 prompt-length audit。

执行与收尾

一模型一卡并行；持续采集 GPU telemetry，随后逐模型 postprocess。

发布保护： 报告生成器要求 pilot、HF reference 与 full CAL 的模型、backend、item count 和 scientific provenance 一致，并验证它们来自同一 repository commit；任何漂移都 fail closed。

Likelihood

比较四个完整选项文本；主分数是每个 continuation token 的平均 log likelihood。

Permutation

每题使用 identity 加两个确定性互异排列，结果重新映射回语义选项后检查一致性。

Strict

只接受单个大写 A–D；拒答与其他格式错误分别统计。

Trust boundary

可复现性与安全边界

已冻结

  • 数据与模型 revision
  • harness commit/tree
  • Python 包与 CUDA wheel
  • split salt、prompt、seed、阈值

运行前验证

  • manifest checksums 与 CAL 对应
  • harness clean + editable source
  • 依赖版本、CUDA 与 GPU
  • runtime fingerprint 与空输出目录

不进入 Git / 本页

  • CAL benchmark 内容
  • runtime 排列输入
  • 原始日志与逐题模型输出
  • 模型 cache、Conda 环境与凭据

数值边界： 固定 Git 状态不能单独保证 GPU 浮点逐 bit 相同；batch_size=auto 也可能受可用显存影响。首次 full CAL 前仍需人工审阅 32-item pilot 的实际 prompt、答案映射和 token denominator。
