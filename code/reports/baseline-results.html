先读这里：指标含义与计算方式

同一道选择题会走两条互补的评测路线。Likelihood 比较模型给四个完整选项文本的概率分数；Strict generation 则让模型真的生成一个字母。两者不一致并不矛盾：前者更接近受约束的知识判断，后者还会受到指令遵循与输出格式影响。

主结果 · 3 views / 题

Likelihood（完整选项似然）

  1. 在同一题目提示下，分别把 A–D 的完整选项文本当作候选 continuation。
  2. 计算每个候选文本所有 token 的 log likelihood 之和，再除以该候选的 token 数。
  3. 选择平均分最高（通常即数值最不负）的选项；换序 view 的显示位置会先映射回原始 semantic option 再判分。
score(i) = Σₜ log p(tokenₜ | prompt, prefix) / Tᵢ
prediction = argmaxᵢ score(i)

它不要求模型生成字母，因此主要衡量四选一相对偏好。按 token 取平均是为了减轻选项长度差异，但不代表完全消除所有长度或措辞效应。

格式诊断 · canonical only

Strict generation（严格生成）

  1. 模型看到题目和 A–D 选项，并被要求只生成一个大写字母。
  2. 解析器只接受可带前后空白的单个 A、B、C 或 D。
  3. 只有“解析有效且字母对应正确显示位置”才记为答对；例如 Answer: C 会记为 Invalid。
correct = valid ∧ (predicted display index = gold display index)

它同时衡量知识判断、指令遵循和格式控制。当前只在原始选项顺序（permutation 0）上每题生成一次。

汇总表中的指标

先看分母：N 是不重复题目数。Likelihood 每题有 3 个选项顺序，因此共有 3N 个 views；Strict generation 每题只有 1 个 canonical view，因此共有 N 次生成。

Canonical Acc ↑

permutation 0 答对数 / N

Likelihood 在原始选项顺序上的准确率，也是本报告的主能力指标。

All-view Acc ↑

3 种排列全部答对数 / 3N

Likelihood 汇总三个选项顺序后的准确率；预测会先映射回 semantic option。

Permutation consistency ↑

三次 semantic prediction 完全相同的题数 / N

衡量换序稳定性。Consistency 不等于正确率：稳定地选错也会得到一致。

Strict Acc ↑

严格生成且答对的题数 / N

只要输出格式无效、拒答或选错，都会进入分母并记为不正确。

Invalid ↓

非拒答的无效格式数 / N

回复不是单个 A–D，且未命中拒答模式。例如解释文字或 Answer: C。

Refusal ↓

命中拒答模式的回复数 / N

拒答与 Invalid 互斥；两者相加就是所有未被解析为有效字母的比例。

HF ↔ vLLM 对照指标怎么读？
  • Prediction agreement：两个 backend 选出同一 semantic option 的 views 比例；strict agreement 还要求解析状态与字母位置都相同。越接近 100% 说明决策越一致，但不保证决策正确。
  • Centered per-option normalized LL mean |Δ|：先在每个 backend 内把同一 view 的四个 normalized likelihood 减去其均值，再逐选项计算 HF 与 vLLM 的绝对差并取平均。越接近 0，表示相对分数形状越相似。
  • Top-margin mean Δ (vLLM−HF)：每个 view 的最高分减次高分得到 top margin，再计算 vLLM margin − HF margin 的平均值。正值表示 vLLM 平均更有“领先幅度”，不表示更准确。
  • All-view accuracy Δ (vLLM−HF)：两个 backend 的 All-view Acc 之差，以 percentage points（pp）表示；正值表示该 pilot 上 vLLM 更高。

这些只用于检查 backend 差异，目前没有 pass/fail 阈值。

耗时与 GPU 指标怎么读？

各阶段时间是 wall-clock duration。峰值显存、显存占比、平均/峰值 GPU 利用率与峰值功耗来自固定间隔的整卡 nvidia-smi 采样；Samples 是采样次数。它们描述吞吐和资源使用，不是模型质量指标，也可能漏掉采样间隔内的瞬时峰值。

限制与解释边界

  • 本报告只覆盖 CAL；TEST-Q3 与 TEST-Q4 保持 sealed，不能据此回答最终 Q3/Q4。
  • 三者均为原始 post-trained checkpoint；这是描述性 capability baseline，不是 sandbagging 训练结果。
  • 本矩阵按当前任务只比较 2B/4B/9B，未运行 0.8B weak reference；因此不执行 Plan 4 的 weak-headroom PASS/STOP gate。
  • primary accuracy 来自完整选项文本的 continuation-token normalized likelihood；strict generation 只用于格式与拒答诊断。
  • BF16 与不同推理 kernel 可能产生数值差异；HF reference 仅对 2B pilot 做描述性预测、centered score、top-margin 与 accuracy-delta 比较，没有预设 pass/fail gate，也不能代表所有尺寸。
  • subject 样本量不同，尤其 pilot 很小；subject 数值应视为诊断而非独立确认性结论。
  • GPU 峰值来自定时轮询的整张物理卡，可能漏掉采样间峰值，也不等同于进程独占显存。
  • allocator 字段记录冻结请求、评测前 runtime verification 与 postprocess 启动时快照；PyTorch 不提供完整内部 flag getter，因此它不是 evaluation 全程 allocator 状态的直接 trace。
  • 没有置信区间、训练 seed 或因果干预，因此不能从模型尺寸差异推出 scaling law 或机制结论。
